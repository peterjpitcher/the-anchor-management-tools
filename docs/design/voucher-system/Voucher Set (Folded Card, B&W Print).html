The Anchor — prize voucher set

Eight voucher types on one folded card design, ready to be generated from the voucher system. Each type prints as two A4 landscape sheets (outside and inside) that fold down the middle into an A5 portrait card. This page is the design source and the developer handover; everything below the spec is the artwork.

The eight vouchers

    Print & fold

    • Sheet size A4 landscape, printed double sided, flip on short edge so the reverse mirrors left to right, not top to bottom. If a test print comes out upside down on the reverse, the flip is wrong.
    • Fold down the middle. Finished card is A5 portrait, crease on the left, opening like a book.
    • Imposition per voucher: sheet 1 outside = [back cover | front cover], sheet 2 inside = [prize | details].
    • Black ink only, no bleed required. Panel labels are screen-only and do not print. There is no printed fold line, fold to the centre of the sheet.
    • Every voucher carries the same QR code on the inside right, linking to what’s on and booking. It is fixed artwork (assets/qr-events-booking.png), not a merge field, so it does not change per voucher.

    Merge fields

    Every variable is marked in the markup with a data-field attribute, so the renderer can bind without touching the layout. Sample values are shown in the artwork below. Expiry date, the event it was won at, and issued by are hand-written on the card, so they print as ruled blanks; the same data-field hooks are on those blanks if they are ever pre-printed instead.

    Controlled voucher-type list

    Title, entitlement wording and system rules must all be driven from one record per type. Staff select a type, they never type the wording. value is the monetary face value in pence, or null for entitlement vouchers.

    idDisplay titleCover titlevalueBookingAlcohol

    A £10 Food & Drink Voucher type is also defined in the terms document but is not in this print set. If it is added later, use the same card design with displayTitle “£10 FOOD & DRINK VOUCHER” and coverTitle “£10 food & drink voucher”.

    Known trade-off: terms are set at 6.5pt

    The full 21 clauses fill the A5 back cover at roughly 6.5pt. That is legal fine-print size and it cannot be enlarged in this format, so a decision is needed before this goes into production. The alternatives, both allowed by the terms document, are: (a) print the key restrictions on the back at a readable size with a QR code or short link to the full terms, or (b) keep the card as it is and issue a separate terms sheet alongside it.

    Required on every generated voucher

    • Voucher title, and the voucher-specific entitlement wording
    • Unique voucher number
    • Expiry date, the event it was won at, and issued by (hand-written on the card)
    • Promoter name and address
    • Full terms (printed on the back cover of this design)
    • A terms version number

    Recommended system rules

    Record per voucher

    • Unique voucher number, voucher type, monetary value where applicable, entitlement description
    • Issue date, expiry date, event it was won at, issued by, terms version
    • Current status: active, redeemed, expired, cancelled, replaced
    • Redemption date and time, team member who processed it, transaction or booking reference
    • Replacement voucher number, where applicable

    Behaviour

    • Build entitlement wording from the controlled type list, never from free text, so the printed title, printed entitlement and system rules cannot contradict one another.
    • Redemption is a single atomic step: verify the number, check status is active and the expiry date has not passed, then mark redeemed with the timestamp, team member and transaction reference. No partial redemption, no splitting across visits.
    • Booking vouchers (requiresBooking: true) are only redeemed once the booking is confirmed. Hold them as active until then.
    • Store the terms version with the voucher and render that version's text. Terms are not applied retrospectively, so an already-issued voucher keeps the wording it was printed with.
    • Replacement: the original must be identifiable, unredeemed and cancellable. Set the original to cancelled, issue a new number, and record it as the replacement.
    • Expire on a schedule rather than only on lookup, so reporting is accurate.
    • Age-restricted types (alcohol: true) should surface an 18+ prompt to the team member at redemption.
